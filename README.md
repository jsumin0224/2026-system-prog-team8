# 🏦 ATM System Programming Project

## 1. 프로젝트 소개

본 프로젝트는 C언어와 Linux 시스템 프로그래밍 기술을 활용하여 ATM(Automated Teller Machine) 시스템을 구현하는 팀 프로젝트입니다.

실제 ATM의 기본적인 금융 거래 기능을 구현하고, 멀티프로세스 및 프로세스 간 통신(IPC), 파일 잠금, 시그널 처리 등의 시스템 프로그래밍 기법을 적용하여 안정적이고 효율적인 ATM 시스템을 개발하는 것을 목표로 합니다.

또한 여러 ATM 프로세스가 동시에 실행되는 환경에서 계좌 데이터의 무결성을 유지하고, 관리자 모니터링 기능을 통해 시스템 상태를 실시간으로 확인할 수 있도록 구현합니다.

## 2. 프로젝트 목표

- termios를 활용한 터미널 입력 및 출력 제어
- fork()를 활용한 멀티프로세스 기반 ATM 시스템 구현
- pipe()를 활용한 부모 프로세스와 자식 프로세스 간 IPC 통신
- fcntl()을 활용한 파일 잠금 및 동시성 제어
- SIGALRM을 활용한 사용자 자동 로그아웃 기능 구현
- 시그널 기반 예외 처리 및 안전한 프로세스 종료
- 관리자용 실시간 시스템 모니터링 및 TUI 구현

## 3. 주요 구현 기능

### 3-1. ATM 클라이언트 UI 및 터미널 제어
- 엔터 키 없이 메뉴를 선택할 수 있는 터미널 인터페이스
- termios를 활용한 터미널 입력 모드 제어
- 비밀번호 입력 시 화면에 `*`만 표시되도록 처리
- ATM 초기 화면 및 거래 메뉴 구성
- 입금, 출금, 계좌이체, 잔액 조회 기능
- 사용자 입력 오류 및 예외 상황 처리 (잘못된 금액, 잘못된 메뉴, 본인 계좌 이체 등)
- ATM마다 별도의 터미널(tty)을 지정하여 입출력 분리

### 3-2. 서버 프로세스 및 IPC 통신
- fork()를 활용한 부모 및 자식 프로세스 생성
- 중앙 은행 서버 역할의 부모 프로세스 구현
- ATM 기기 역할의 자식 프로세스 관리
- pipe()를 활용한 프로세스 간 통신
- poll()로 여러 ATM의 요청을 동시에 대기하고 순차 처리
- ATM 거래 요청 및 처리 결과 전달
- 서버와 클라이언트 간 통신 프로토콜 정의 (`Request` / `Response` 구조체)

### 3-3. 데이터 관리 및 파일 잠금
- 계좌 정보 파일(`accounts.dat`) 생성 및 관리 (권한 0600)
- fcntl()을 활용한 파일 잠금 구현
- 여러 ATM 프로세스의 동시 계좌 접근 제어
- 입금, 출금 및 계좌이체에 따른 잔액 관리
- 계좌이체는 하나의 쓰기 잠금 안에서 출금과 입금을 함께 처리
- 거래 내역 파일(`transactions.log`)에 텍스트 한 줄씩 기록
- 파일 입출력 오류 확인 및 잔액 오버플로 방지

### 3-4. 시그널 처리 및 관리자 모니터링
- SIGINT, SIGTERM을 활용한 안전한 프로세스 종료와 터미널 설정 복구
- SIGALRM을 활용한 자동 로그아웃 기능 (로그인 후 30초 동안 입력이 없으면 초기 화면 복귀)
- 실행 중인 ATM 프로세스 상태 확인 (/proc 스캔)
- 현재 접속 사용자 확인 (utmp)
- 거래 로그 파일 크기 및 수정 시간 확인 (stat)
- 최근 거래 내역 표시 (파일 끝에서부터 읽기)
- 1초 주기로 화면을 갱신하는 관리자 전용 TUI 모니터링 화면 구현

## 6. GitHub 브랜치 전략

본 프로젝트는 Git Flow 방식의 브랜치 운영 구조를 참고하여 협업을 진행합니다.

| 브랜치 | 용도 |
|---|---|
| main | 최종 제출 및 안정화된 코드 |
| develop | 팀원별 개발 코드 통합 및 테스트 |
| feature/client-ui | 담당자 A의 클라이언트 개발 |
| feature/server-ipc | 담당자 B의 서버 및 IPC 개발 |
| feature/file-locking | 담당자 C의 파일 잠금 및 데이터 관리 |
| feature/signal-monitor | 담당자 D의 시그널 및 모니터링 개발 |

### 브랜치 병합 규칙
1. 각 담당자는 자신의 feature 브랜치에서 기능을 개발합니다.
2. 작업이 완료되면 변경 사항을 Commit 및 Push 합니다.
3. 자신의 feature 브랜치에서 develop 브랜치로 Pull Request를 생성합니다.
4. 팀원 간 코드 검토 및 테스트 후 develop에 병합합니다.
5. 전체 기능 통합 및 테스트가 완료되면 develop을 main에 병합합니다.

## 9. 빌드 및 실행 방법

### 빌드

```
make clean && make full && make monitor
```

| 명령 | 결과 |
|---|---|
| `make full` | `atm_server` (서버 + 클라이언트 UI) |
| `make stub` | `atm_stub_server` (UI 없이 스크립트로 서버 테스트) |
| `make monitor` | `atm_monitor` (관리자 모니터) |
| `make clean` | 빌드 결과물과 `accounts.dat`, `transactions.log` 삭제 |

헤더 파일을 수정했을 때는 반드시 `make clean`을 먼저 실행합니다.

### 실행

**ATM 1대로 실행**

```
./atm_server 1
```

**ATM 여러 대를 각각 다른 터미널에서 실행**

1. ATM으로 사용할 터미널 창마다 `tty`를 입력해 경로(`/dev/pts/N`)를 확인합니다.
2. 같은 창에서 `sleep 1000000`을 실행하여 쉘이 입력을 가로채지 않게 합니다.
3. 서버 창에서 확인한 경로를 순서대로 넘겨 실행합니다.

```
./atm_server /dev/pts/5 /dev/pts/7
```

**관리자 모니터 (서버와 같은 폴더에서 실행)**

```
./atm_monitor
```

## 10. 설계 요약

### IPC 프로토콜
- ATM(자식)은 `Request` 구조체를 요청 파이프로 보내고, 서버(부모)는 `Response` 구조체를 응답 파이프로 돌려줍니다.
- 지원 동작: 로그인(`OP_LOGIN`), 입금(`OP_DEPOSIT`), 출금(`OP_WITHDRAW`), 이체(`OP_TRANSFER`), 잔액 조회(`OP_BALANCE`)
- 서버는 `poll()`로 모든 ATM의 요청을 기다리고 한 건씩 처리합니다.

### 거래 로그 형식

`transactions.log`에 거래마다 한 줄씩 기록합니다.

```
시간 | 계좌 | 종류 | 금액 | 거래 후 잔액 | 상대 계좌
```

종류는 `DEPOSIT`, `WITHDRAW`, `TRANSFER` 중 하나이며, 이체는 한 건이 `TRANSFER` 한 줄로 남습니다.

### 자동 로그아웃
- 로그인 후 입력 대기가 시작될 때마다 `alarm()` 타이머를 새로 설정합니다.
- 입력 없이 시간이 지나면 SIGALRM으로 대기가 중단되고 `INPUT_TIMEOUT`이 반환되어 로그인 화면으로 돌아갑니다.
- 로그인 전 화면에서는 타이머가 꺼져 있습니다. 시간은 `client/terminal.c`의 `IDLE_TIMEOUT_SEC`로 조절합니다.

### 모니터링
- 1초마다 화면을 다시 그리는 실시간 TUI 방식으로 동작합니다.
- 백그라운드(데몬) 실행 모드는 실시간 화면과 목적이 맞지 않아 제외했습니다.
