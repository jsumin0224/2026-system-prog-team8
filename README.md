# 🏦 ATM System Programming Project

## 1. 프로젝트 소개

본 프로젝트는 C언어와 Linux 시스템 프로그래밍 기술을 활용하여 ATM(Automated Teller Machine) 시스템을 구현하는 팀 프로젝트입니다.

실제 ATM의 기본적인 금융 거래 기능을 구현하고, 멀티프로세스 및 프로세스 간 통신(IPC), 파일 잠금, 시그널 처리 등의 시스템 프로그래밍 기법을 적용하여 안정적이고 효율적인 ATM 시스템을 개발하는 것을 목표로 합니다.

또한 여러 ATM 프로세스가 동시에 실행되는 환경에서 계좌 데이터의 무결성을 유지하고, 관리자 모니터링 기능을 통해 시스템 상태를 확인할 수 있도록 구현합니다.

## 2. 프로젝트 목표

- `termios`를 활용한 터미널 입력 및 출력 제어
- `fork()`를 활용한 멀티프로세스 기반 ATM 시스템 구현
- `pipe()`를 활용한 부모 프로세스와 자식 프로세스 간 IPC 통신
- `fcntl()`을 활용한 파일 잠금 및 동시성 제어
- `SIGALRM`을 활용한 사용자 자동 로그아웃 기능 구현
- 시그널 기반 예외 처리 및 안전한 프로세스 종료
- 관리자용 시스템 모니터링 및 TUI 구현

## 3. 주요 구현 기능

### 3-1. ATM 클라이언트 UI 및 터미널 제어

- 엔터 키 없이 메뉴를 선택할 수 있는 터미널 인터페이스
- `termios`를 활용한 터미널 입력 모드 제어
- 비밀번호 입력 시 화면에 문자가 표시되지 않도록 처리
- ATM 초기 화면 및 거래 메뉴 구성
- 입금, 출금, 계좌이체, 잔액 조회 기능
- 사용자 입력 오류 및 예외 상황 처리

### 3-2. 서버 프로세스 및 IPC 통신

- `fork()`를 활용한 부모 및 자식 프로세스 생성
- 중앙 은행 서버 역할의 부모 프로세스 구현
- ATM 기기 역할의 자식 프로세스 관리
- `pipe()`를 활용한 프로세스 간 통신
- ATM 거래 요청 및 처리 결과 전달
- 서버와 클라이언트 간 통신 프로토콜 정의

### 3-3. 데이터 관리 및 파일 잠금

- 계좌 정보 파일 생성 및 관리
- `fcntl()`을 활용한 파일 잠금 구현
- 여러 ATM 프로세스의 동시 계좌 접근 제어
- 입금, 출금 및 계좌이체에 따른 잔액 관리
- 거래 내역 파일 기록
- 파일 입출력 오류 및 데이터 무결성 관리

### 3-4. 시그널 처리 및 관리자 모니터링

- `SIGINT`를 활용한 안전한 프로세스 종료
- `SIGALRM`을 활용한 자동 로그아웃 기능
- 일정 시간 입력이 없을 경우 초기 화면 복귀
- 실행 중인 ATM 프로세스 상태 확인
- 거래 로그 파일 크기 및 수정 시간 확인
- 관리자 전용 TUI 모니터링 화면 구현

## 6. GitHub 브랜치 전략

본 프로젝트는 Git Flow 방식의 브랜치 운영 구조를 참고하여 협업을 진행합니다.

| 브랜치 | 용도 |
|---|---|
| main | 최종 제출 및 안정화된 코드 |
| develop | 팀원별 개발 코드 통합 및 테스트 |
| feature/client-ui | 담당자 A의 클라이언트 개발 |
| feature/server-ipc | 담당자 B의 서버 및 IPC 개발 |
| feature/file-locking | 담당자 C의 파일 잠금 및 데이터 관리 |
| feature/signal-monitor | 담당자 D의 시그널 및 모니터링 개발 |

### 브랜치 병합 규칙

1. 각 담당자는 자신의 feature 브랜치에서 기능을 개발합니다.
2. 작업이 완료되면 변경 사항을 Commit 및 Push 합니다.
3. 자신의 feature 브랜치에서 develop 브랜치로 Pull Request를 생성합니다.
4. 팀원 간 코드 검토 및 테스트 후 develop에 병합합니다.
5. 전체 기능 통합 및 테스트가 완료되면 develop을 main에 병합합니다.
